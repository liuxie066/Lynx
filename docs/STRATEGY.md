# 一期规则与数据口径

## 固定参照

OM 本地 main：7386ff8bb94ce14a3f5955f8c5a429d6c8f58261，只读参照。核心来源：domain/domain/engine/candidate_engine.py、domain/domain/fee_calc.py、src/application/short_vol_metrics.py、src/application/opening_quote_evidence.py、src/application/config_defaults.py、domain/domain/fx_quote_policy.py。Lynx 使用 Swift 实现，不导入 OM 的运行配置、账户或 Python 环境。

明确差异：不读取真实资产、不做容量资格与集中度排序，CC 无成本门槛；CSP 最高行权价是接货上限。人工刷新在休市时只核验连接 / 市场状态并保留历史，不计算新的休市参考推荐。OI 保留未知语义并用于排序；不把旧模板中未进入当前正式候选规则的 OI / 成交量字段另加为资格门槛。

## 价格、费用和收益

卖出参考限价为买卖中间价按最小价位向上取整，不使用最新成交价替代有效买卖报价，不代表实际可成交价格。一手真实股数取快照 contractSizeFloat（缺失时 contractSize）并与期权链 lotSize 核对；存在的 contractMultiplier 也须一致，缺失不能回填 100。

- 毛权利金 = 参考限价 × 一手股数；净权利金 = 毛权利金 − 估算卖出费用。
- CSP 担保现金 = strike × 股数；持有期收益率 = 净权利金 / (担保现金 − 净权利金)。接货净折价 = (spot − (strike − 净权利金 / 股数)) / spot。
- CC 持有期净权利金收益率 = 净权利金 / (spot × 股数)。上行空间 = (strike − spot) / spot；不含真实持仓成本回报。
- 年化 = 持有期收益率 × 365 / 市场本地日历 DTE，不用于主排序。
- 费用 / 金额输出保留 6 位、收益比例 10 位、IV/RV 指标 6 位小数。分档边界按同样 10 位精度处理，保证恰好相差 0.002 的值进入同档，避免二进制浮点额外拆档。

费用版本 futu_option_sell_fee.v1。US 候选采用平台费上界每手 0.60；HK 采用 Tier 1 上界。其余佣金、监管及结算费用与固定基线一致。来源：[Futu HK US](https://www.futuhk.com/en/support/topic2_283)、[Futu HK HK](https://www.futuhk.com/en/support/topic2_335)。不是实时抓取费率；不同券商地区尚未逐一核验。

## 证据与缺失

仅常规开市状态计算新推荐。标的状态须正常且未停牌，原始现价时间距决策不超过 300 秒；期权需标准合约、正确标的 / 方向、有效股数、最小价位、报价和 Delta。已知无买价或明确非标准合约是排除原因；未知字段不是零。

IV 从 OpenD 百分数转为小数。RV 用前复权日线：从扫描日到到期日统计交易日，回看 max(20, 剩余交易日数) 个收益期，取此前对应完整交易日的收盘价，计算对数收益样本标准差 × √252。任何必要收盘日缺失都不作旧 RV 回退。

交易日历首先取 OpenD。港股 2026 跨 2027 的 RV 使用固定的 HKEX CT/077/26 官方证券日历，与 OpenD 返回的未来日期核对，冲突则不可用；半日算一个日收盘。该来源不推算 2028 或临时停市。其他无法核实的未来覆盖保留不可用，不靠一般工作日猜测。

财报硬窗口为 max(扫描日, 到期日−6 个日历日) 至到期日，包含两端；该区间内存在未来财报则排除。日历请求失败或日期未知不能当作无财报。

最低净权利金 CNY 换算沿用 OM 的腾讯 USDCNY / HKDCNY 来源及 CFETS 2026 会话 / 假日日历。汇率时间须有效且属于最近有效交易会话；已证实休市可沿用会话报价。未知年份没有默许兜底，日历需随 App 维护更新。

## 排序

每股票先按持有期收益率降序取档首，纳入收益不低于档首−0.002 的候选；按档内指标排序后再开始下一档，不做相邻链式合并。

CSP 档内：接货净折价高、价差小、OI 已知且高、净权利金高、合约稳定 ID 升序。CC 标的内第一项改为 strike 高；跨股票第一项改为上行百分比大，其余相同。跨股票从各股票最佳合约中取代表，再按同样收益分档选择最多三个。稳定 ID 为市场和 OpenD 合约代码，完全相同时按标准股票代码及合约代码升序。

四个列表分别维护完整成功基线。只比较前三合约 ID、顺序和数量；数值变化、不完整结果、失败不改变通知基线。配置变更清空对应市场基线，下一次完整成功重新建立基线而不通知。结果保留扫描参数与时间，旧解释不套用新配置。
