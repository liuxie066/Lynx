# Lynx 初版产品需求文档

日期：2026-11-24。状态：初版需求，尚未实施。

本文的“已确认”表示产品要求已确定，不表示功能已完成。“建议”用于辅助后续技术决策；“待确认”不能作为已批准的实现约束。当前仓库仅交付文档与 MIT 许可证，不包含 App、技术原型、行情验证或发布产物。

## 1. 产品定位与目标（已确认）

Lynx（猞猁）是面向其他投资者的独立、本地 Mac App，帮助用户在港股和美股中查看 CSP（现金担保卖出看跌期权）及 CC（备兑卖出看涨期权）的模拟机会，理解候选合约及排序原因。

- 支持 Apple Silicon M1 及以后，不支持 Intel。
- 首期券商为富途 / moomoo，通过用户自装的官方 OpenD 获取行情。
- 不依赖开发者服务器，不做云同步。
- 券商接入为 App 内部插件，首期随 App 提供；不是其他软件的插件，也不做插件商店。
- 用户无需自行安装 Python 开发环境，无论最终是否随包保留 Python。
- 仓库公开，项目采用 MIT 许可证，见 [LICENSE](../LICENSE)。

## 2. 范围与模拟边界（已确认）

首期只做行情和模拟分析，不读取真实现金、持仓、账本，不选择或读取交易账户，不下单、撤单或执行交易。连接 OpenD 与检查行情权限即可，不以真实账户查询作为使用前置条件。

所有计算按一手期权模拟，使用真实合约乘数；不能假定所有合约乘数均为 100。所需字段缺失时沿用适用的数据缺失语义，不能凭空补乘数或把未知当零。

| 方向 | 用户输入 | 模拟含义 | 结果边界 |
| --- | --- | --- | --- |
| CSP | 愿意接货的最高价 | 模拟卖出一手看跌期权，展示所需担保现金 | 不证明用户有足够现金 |
| CC | 模拟每股成本 | 假设已有足够股票覆盖一手期权 | 不证明用户真实持股 |

输入币种随标的。结果明确标注“模拟”；每手净权利金、担保现金等按对应合约规模计算，不把一手期权简单等同于 100 股。

首期不做真实组合容量评估、真实集中度管理、券商登录凭据托管、OpenD 安装或进程代管。

## 3. 用户流程与设置（已确认）

1. 用户自行安装、登录并保持官方 OpenD 可用。Lynx 提供引导、连接状态及行情权限检查，默认连接本机，端口可调。
2. 用户添加关注股票，按股票分别打开 CSP、CC，可同时开启两个方向。
3. CSP 填愿意接货的最高价；CC 填模拟每股成本。缺少某方向必填项时，仅该方向显示“待设置”，不阻塞另一方向或其他股票。
4. 期限等高级策略参数采用适用的 OM 默认值，默认收起；用户可展开修改并恢复默认。具体数值须核对后确定，本文不填未经验证的默认值。
5. 用户手动刷新，或选择定时刷新；按“美股或港股 → CSP 或 CC → 股票列表”查看结果。
6. 展开某只股票，查看其他所有合格期限、行权价合约和该股票内部的排序。无合格结果或未入选时，可以查看对应原因。

费用不属于用户可修改的高级设置，相关来源见第 8 节。

## 4. 计算、筛选与排序（已确认规则）

### 4.1 与 OM 的关系

OM 指用于参照策略规则的 options monitor。Lynx 复用其适用计算规则、门槛和缺失语义，但有明确差异，不能宣称完全没有策略差异：

- 去掉基于真实账户容量的资格判断。
- 去掉跨标的排序中的集中度因素。
- CC 成本由用户手填模拟每股成本提供。
- 输出为一手期权模拟结果，不作账户可交易性保证。

除上述差异外，其余适用门槛及缺失语义保留。未知值不能当零；已知持仓、现金或账户容量不是任何模拟方向的前置数据。适用规则清单、固定对照基线、公式细节和默认参数仍需后续核验，不能把未核验部分称为已完成移植。

### 4.2 先按持有期收益分档

| 方向 | 用于分档的收益口径 |
| --- | --- |
| CSP | 持有期净收益率 |
| CC | 持有期净权利金收益率 |

先按相应持有期收益率从高到低，以 `0.002`（即 **0.2 个百分点**）分档。每档以该档最高收益率为锚，不能用相邻候选的差距进行链式合并。较高收益档在前，再按档内规则比较；年化收益率不主导排序。

例如收益率为 10.00%、9.85%、9.70% 时，前两项距最高值不足 0.2 个百分点，可以同档；第三项距 10.00% 为 0.3 个百分点，不能因它与 9.85% 相邻且差距较小而并入同档。阈值恰好相等的边界与精度处理需随 OM 对照核验。

### 4.3 档内排序优先级

以下按从左到右依次比较，前项相同再比较后项。价差使用适用 OM 口径；OI 为未平仓量，未知 OI 不转成零，也不被视为已知值。

| 比较范围 | 方向 | 档内优先级 |
| --- | --- | --- |
| 同一股票的合约 | CSP | 接货折价大 → 价差小 → OI 已知且高 → 净权利金高 → 稳定 ID |
| 同一股票的合约 | CC | 行权价高 → 价差小 → OI 已知且高 → 净权利金高 → 稳定 ID |
| 不同股票的代表合约 | CSP | 接货折价大 → 价差小 → OI 已知且高 → 净权利金高 → 稳定 ID；不含集中度 |
| 不同股票的代表合约 | CC | 行权价高于现价的百分比大 → 价差小 → OI 已知且高 → 净权利金高 → 稳定 ID |

跨股票 CC 的首个档内指标为 `(strike - spot) / spot`，不比较不同股票的绝对行权价。无有效现价时不能编造比例，需按适用缺失语义处理。稳定 ID 用于完全相同情况下的确定性顺序，具体 ID 定义及比较方向待核验。

### 4.4 展示与推荐

形成美股 CSP、美股 CC、港股 CSP、港股 CC 四个独立列表：

- 每只存在合格候选的股票先按标的内排序选出最佳合约，股票列表展示全部股票的最佳合约，不仅展示推荐前三名。
- 对各股票的代表合约按跨标的规则排序，每个列表取前三个作为模拟推荐；不足三个不凑数。
- 展开股票展示其他全部合格期限、行权价合约及标的内顺序，不只展示同一期限或单个行权价。
- 未入选推荐但仍有合格合约的股票保留结果和排序解释；无合格合约、未满足条件、待设置或数据不可用的股票展示相应原因，不混同为零收益。
- 结果包含每手净权利金、相应持有期收益、到期日、行权价、接货折价或上行空间以及解释；CSP 另展示所需担保现金，CC 明示模拟成本及覆盖假设。

## 5. 刷新、市场状态与失败处理（已确认）

支持手动刷新和定时刷新，定时间隔选项为：关闭、10 分钟、30 分钟、1 小时。两个市场共用间隔，分别判断开市、休市；自动刷新跳过休市市场，两边都休市时暂停。手动刷新共用同一任务；其在休市时的取数边界待细化，不据此承诺休市仍有实时行情。

| 场景 | 要求 |
| --- | --- |
| 定时到点 | 根据市场状态刷新适用市场 |
| 上一轮尚未结束 | 单轮不重入；本次触发跳过，不排队积累 |
| 进行中点击手动刷新 | 共用当前任务和进度，不启动重叠轮次 |
| 开始刷新 | 保留旧结果及其时间，同时显示刷新中 |
| 某市场成功 | 更新该市场结果及上次成功时间 |
| 某市场失败 | 保留该市场旧结果，明确旧数据、时间与失败原因；不抹掉另一市场的健康结果 |
| 系统睡眠 | 不执行刷新 |
| 系统唤醒且已到期 | 在满足市场等刷新条件时只补一次，不补跑所有错过的周期 |

每个市场独立展示状态与上次成功时间，不能让一个市场的成功掩盖另一个失败。失败或不完整结果不作为推荐变化通知的输入；部分数据如何用于页面展示及何时认定一轮完整，列为待细化事项。

## 6. 窗口、菜单栏与系统生命周期（已确认）

- 关闭窗口后 App 留在菜单栏，继续按刷新规则运行；首次关窗提醒用户这一行为。
- 菜单栏提供：打开窗口、立即刷新 / 当前进度、刷新间隔、上次成功时间、连接状态和退出。市场状态与时间可分别辨认。
- 退出 App 停止 App 自有任务，不停止用户的 OpenD。
- 开机启动默认关闭，用户可主动开启。

## 7. 通知（已确认，部分基线细节待细化）

默认仅更新界面，不发送通知。提供两个独立开关：“推荐前三变化”“连接异常”。仅在用户开启通知时申请系统通知权限，不在首次启动时无条件申请。

### 推荐变化

- 四个市场策略列表分别建立和比较基线。
- 首次成功得到完整结果仅建立基线，不通知。
- 推荐合约身份、顺序或数量变化才通知；仅价格、净权利金或收益率数值变化不通知。
- 失败或不完整结果不能伪装成推荐数量减少或清空，不触发推荐变化通知。
- 通知点击后进入对应的市场与策略页面。

### 连接异常

- 同一故障只提醒一次，避免每次刷新重复打扰。
- 连接恢复后再次发生故障，可以再次提醒。
- 点击通知打开对应连接状态页面。

用户修改关注列表、策略开关、参数、通知设置后如何重建基线，以及何种事件构成同一故障、权限被拒后的交互，仍需细化；不把这些细节默认为已确认行为。

## 8. 券商插件、OpenD 与费用（已确认）

首期富途 / moomoo 接入实现为 App 内部随包插件。插件划分用于承载券商接入与费用适配，不引入插件商店或其他软件的插件协议。

用户负责官方 OpenD 的安装、登录、运行及升级；App 只做引导、连接状态和行情权限检查，默认本机连接且端口可调。不内置、下载、启动或停止 OpenD，不收取券商登录凭据。

费用按适用 OM 规则计算，由项目维护者维护，随券商插件或 App 发布更新，不实时抓取费率，用户不可修改。收益计算、筛选和排序必须使用同一套费用模型。结果提示：“手续费为估算，以实际账户收费为准。”

不同地区富途 / moomoo 费率的适配范围及差异需要核验；在完成之前不能宣称一个费用模型适用于所有地区和账户。

## 9. 本地保存与重新打开（已确认）

自动保存以下内容：关注股票、每股票策略开关、接货价 / 模拟每股成本、高级策略参数、刷新与通知偏好、最近结果及其时间。不做云同步。

重新打开 App 时，先展示带时间的历史结果，让用户能识别数据的新旧。只有自动刷新已开启、相应市场开市且已到刷新时间时，才触发自动刷新；不因启动就无条件刷新。具体本地存储技术和通知基线持久化方案待确认。

## 10. 技术栈选型建议（未定案、未验证）

**这是选型建议，最终技术栈仍待确认。** 倾向以 SwiftUI 提供原生 Mac 窗口、菜单栏及系统交互体验；是否保留随包 Python，取决于后续接入验证、计算一致性和维护成本。不能将 Swift 原生连接 OpenD 的能力视为已经验证。

| 路线 | 价值 | 成本与需验证的条件 |
| --- | --- | --- |
| 全 Swift / SwiftUI | 原生体验；部署运行环境统一，无需维护额外 Python 运行时 | 需确认 OpenD 原生协议 / SDK 可行性及字段覆盖；移植策略和费用逻辑需要一致性验证，OM 与 Lynx 双实现存在持续维护成本 |
| SwiftUI + 随包 Python 计算进程 | 原生界面，同时有机会复用 OM 计算代码及 Python 生态 | 需处理 Python 随包打包、签名、子进程生命周期和进程接口；代码复用还受原许可约束，不能假设可直接复制 |

建议的条件化选择：

1. 后续另行授权验证 Swift 连接用户自装 OpenD，确认必要行情字段完整，包括真实合约乘数以及策略计算所需数据。
2. 用固定相同输入对照 OM 的计算、费用、筛选和排序；明确排除已批准的模拟输入、去掉真实账户容量资格及去掉集中度等差异，其余差异须解释。
3. 若接入可行、计算一致性可维护且移植成本可接受，倾向全 Swift / SwiftUI，以统一运行环境。
4. 若现有 Python 生态和复用价值明显、Swift 移植或维护成本过高，可保留随包 Python 计算进程；仍保证用户无需自行安装 Python 开发环境。

本地保存、后台调度、通知和开机启动优先评估系统能力，避免为首期引入不必要框架。此建议不指定具体数据库、IPC、最低 macOS 版本或签名分发方案，也不改变 App 退出即停止自有任务的产品边界。

本轮只记录建议，不进行原型、依赖安装、真实行情请求或 App 实现。

## 12. 产品验收标准（未来实施时验证）

以下是后续产品验收目标，当前均不能据本文视为已通过。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A01 | Apple Silicon 上首次使用 | 引导连接用户自装 OpenD，仅检查行情连接和权限，不要求选择交易账户、读取真实资产或安装 Python 开发环境 |
| A02 | 同股票开启 CSP 和 CC，缺少一个方向的输入 | 仅缺输入方向待设置，另一方向和其他股票继续可用，币种随标的 |
| A03 | 使用乘数不为 100 的期权合约 | 一手金额按真实乘数计算；CSP 显示担保现金，CC 显示模拟成本与覆盖假设，均不证明真实资产足够 |
| A04 | 查看四个市场策略列表 | 展示每股票最佳合约，各取最多三个模拟推荐，不足不凑；展开能看到所有其他合格期限和行权价 |
| A05 | 构造相邻收益差小但离档首过远的候选 | 按 0.002 及档内最高收益锚分档，不发生链式合并；年化不主导排序 |
| A06 | 同档候选及跨股票 CC 候选 | 逐项符合第 4.3 节优先级；跨股票 CC 比上行百分比，不比绝对 strike；不含集中度 |
| A07 | OI、费用输入或其他必要数据未知 | 保留未知语义及适用门槛，不按零值计算；能看到不满足条件或数据不可用原因 |
| A08 | 修改与恢复高级参数 | 可展开修改并恢复经核验的默认值，费用不提供用户编辑入口 |
| A09 | 定时到点时一市场休市、另一市场开市 | 使用同一间隔，分别判市，只自动刷新适用市场；两边休市时暂停 |
| A10 | 刷新慢、重叠触发、系统睡眠后唤醒 | 单轮不重入，不排队；手动共用任务；睡眠不刷新，唤醒到期最多补一次 |
| A11 | 一个市场成功、另一个失败 | 两市场状态及时间独立；旧结果在刷新中保留，成功更新，失败标旧，不抹掉健康市场结果 |
| A12 | 关窗、退出 App、开机启动设置 | 首次关窗提醒，菜单栏继续工作并提供第 6 节入口；退出停止自有任务且 OpenD 不受影响；开机启动默认关 |
| A13 | 通知默认状态及首次完整成功 | 默认不通知；两个开关独立，仅开启时申请权限；首次成功建立基线不通知 |
| A14 | 四列表中某一推荐变化、纯数值变化或刷新失败 | 合约 / 顺序 / 数量变化才通知对应列表；纯数值变化及失败 / 不完整结果不触发推荐变化通知 |
| A15 | 连续同一连接故障、恢复后再次故障 | 同一故障只通知一次，恢复后再次故障可通知，点击进入对应页面 |
